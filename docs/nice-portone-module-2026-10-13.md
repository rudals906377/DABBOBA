# 나이스페이 · 포트원 V2 모듈 준비

2026-10-13 최초 준비는 **포트원을 통한 나이스 결제**다. 후속 사용자 결정으로 심사 웹은 나이스와 토스 직접 결제를 함께 지원한다 (`shared-payment-review-2026-10-13.md`). 이 문서의 로컬 구현·합성 PG 시험과 실제 채널 저장·배포·승인은 구분한다.

## 콘솔 확인

- 대표자 다뽀바 계정에 로그인된 포트원 상점이 기존 결제시험 프로필의 상점과 일치한다.
- 실연동에는 등록된 채널이 없었다. TEST에는 기존 이니시스·KCP만 있었다.
- 나이스정보통신 **신모듈(V2 지원)**, 일반 결제창 공용 TEST MID `iamport00m`을 선택하고 `DABBOBA_NICE_TEST` 이름을 입력했다. Key·결제취소 비밀번호는 포트원 제공 시험 값이며 노출·복사·재발급하지 않았다.
- 채널 저장·시험 연결을 사용자에게 질문했고 아직 답변 전이다. **저장 버튼을 누르지 않았고 실제 나이스 채널 키는 아직 없다.**

## 코드 준비

- 서버: `PORTONE_V2_NICE` 기본 카드 레일, `NICE_V2` 응답 검증, 주문/배송비의 채널 스냅샷, 조회·웹훅·취소/환불·작업자 재조회에 연결했다. 기존 원장/멱등 처리 흐름을 재사용한다.
- 설정은 결제시험 프로젝트 `lyzcyrdiazorjaqlgblr`와 두 STAGING 등급·TEST 채널로 한정한다. NICE LIVE와 운영 프로젝트 설정은 시작 단계에서 차단한다.
- 기본 `PORTONE_CHANNEL_KEY`에는 발급된 NICE TEST 채널을 지정한다. 기존 이니시스 채널은 `PORTONE_INICIS_CHANNEL_KEY`, 기존 KCP 채널은 `PORTONE_KCP_CHANNEL_KEY`에 보존한다. 같은 상점·같은 환경에서만 조회하며 공개 결제수단 목록에는 NICE만 노출한다.
- Native: 서버 주문의 `cardPayment`를 우선 사용해 설치된 이전 이니시스 채널로 나이스 주문을 보내지 않는다. 잘못된 provider/pgProvider 조합은 차단하고, 채널 스냅샷이 없는 과거 주문만 기존 빌드 설정을 사용한다. 화면 문구는 특정 과거 PG명이 아닌 신용카드 결제로 표시한다.
- SQL 0097은 NICE 주문의 비어 있거나 다른 PG로 위조된 채널 스냅샷을 차단한다. 기존 결제 provider/채널 불변 트리거를 보존하며 과거 결제 기록을 재작성하지 않는다.
- 이니시스에만 해당하는 결제창 미제출 금액 예외를 NICE에 확대하지 않았다. 통신 오류나 불명확한 승인 결과는 성공/미결제로 단정하지 않는다.

## 남은 연결 순서

1. 사용자의 TEST 채널 저장·시험 연결 승인 후 포트원에서 저장하고 생성된 채널을 새로고침으로 확인한다. 실제 채널 키를 임의 생성하지 않는다.
2. 결제시험 DB의 현재 83개 이력과 번호 변경 매핑을 대조한다. 이미 적용된 구 파일명 `0082_portone_card_channel_binding.sql`은 동일 SQL 재실행 대상이 아니다. 후속 마이그레이션·백업·법적 문서 게시 순서를 확인하고 변경 범위를 명시한 뒤 적용한다. 전체 운영 DB에는 적용하지 않는다.
3. 기존 시험 프로필을 보존한 새 NICE 시험 프로필에 발급된 채널을 설정한다. 이니시스/KCP 과거 채널과 서버 전용 시크릿을 유지하고, 토스 키·직접 연동 provider를 섞지 않는다.
4. 후속 사용자 요청으로 `/review/`의 NICE·토스 공통 지원 범위가 승인되어 구현됐다. PortOne SDK·Toss SDK, 명시적 TEST 결제사 선택, 주문별 결제사 고정, 복귀 검증과 심사 전용 CSP를 적용했다. 실제 채널 저장 및 서버 설정 연결은 여전히 별도다.
5. 승인된 시험 환경만 배포하고 실제 심사 로그인, NICE 카드창 열기/닫기·조회 복구를 확인한다. 카드 입력·최종 결제는 직접 수행하지 않는다. 실기기 시험과 실제 PG/웹훅 수신은 별도 증거가 필요하다.
6. LIVE는 나이스 계약 승인 및 실제 MID·키·신용카드/부분취소 권한을 확인한 뒤 별도 연결한다. PG 처리업체 안내/개인정보처리방침의 이니시스 표기와 새 문서 버전, 공식 릴리스·배포 검증기도 그때 맞춘다. 현재 코드가 운영 결제 활성화까지 완료된 것은 아니다.

## 공식 근거

- https://developers.portone.io/opi/ko/integration/pg/v2/nice-v2
- 현재 설치된 공식 PortOne server-sdk의 `PgProvider` 타입에도 `NICE_V2`가 정의되어 있다. 브라우저 요청은 `channelKey`, `payMethod: CARD`, 서버가 저장한 금액/결제 ID를 사용한다.
- 모든 실제 결제수단과 부분 취소 등의 기능은 PG 사전 신청·계약 조건을 확인해야 한다. 신청 완료만으로 승인 또는 운영 결제 가능으로 표시하지 않는다.

## 검증

- 설정 41건, PG 어댑터/채널/Native 선택 및 결제 상태 단위시험 42건, 작업자 재조회 5건 통과.
- API·작업자·Expo TypeScript 검사 통과. 합성 시험 값만 사용했다.
- 일회용 PostgreSQL 17에 전체 98개 마이그레이션 적용 성공. 실제 DB 통합시험 11건 통과: NICE 주문 스냅샷과 기존 PG의 신규 주문 차단, 스냅샷 위조 차단, PG 응답 유실 후 조회 복구·중복 지급 방지, 늦은 승인 환불 검토, 전액 환불의 1회 처리 및 미사용 가챠의 뽑기권/재고 복구. 이니시스/KCP 회귀도 함께 통과했다. PG HTTP 응답만 합성이므로 실제 나이스 승인·취소 증거는 아니다.
- 공용 웹 빌드·고객 API/작업자 Edge 번들·보호 런타임 검사 통과. 기존 큰 청크 및 모듈 유형 빌드 경고는 남았고 이번 결제 모듈 변경으로 처리하지 않았다.
- 실제 PortOne NICE 채널 저장·NICE 결제창·PG 승인·배포·실기기 시험은 아직 미검증이다.
