# 출시 전 돈·탈퇴 경로 점검 (2026-10-06)

돈이 움직이는 경로를 네 영역으로 나눠 코드를 다시 읽었다: 결제·주문, 환불, 뽑기·보관·포인트·교환, 탈퇴. 아래는 확인된 문제와 처리 상태다.

이중 결제, 이중 환불, 결제 금액보다 큰 환불, 다른 계정 삭제 같은 문제는 나오지 않았다. 각 영역에서 확인한 부분은 다음과 같다.

- 결제·주문
  - 주문 멱등성
  - 결제사 이벤트 중복 제거
  - 서버 가격 재계산
  - PortOne 금액·채널·결제수단 검증
- 환불
  - 부분 환불 산정식
  - 포인트 1회 복원
  - 전액·부분 환불 상호 배제
- 뽑기
  - 뽑기 확정 잠금과 결과 재생
  - 남은 수량 비례 확률
  - 포인트 환급 적격 조건

## 오늘 고친 것

| 영역 | 문제 | 결과 |
|---|---|---|
| 결제 | 결제 확인 전에 이상 상태·금액 불일치·부분 취소 알림이 오면 주문이 검토 상태가 된 채 재고 예약·사용 포인트·배송 보류가 영영 풀리지 않음 | 결제 실패와 같은 방식으로 즉시 풀고 `cancelled_at` 기록. 실제로 돈이 잡혔으면 기존 늦은 결제 환불 경로로 처리 |
| 환불 | 취소 결과를 모르는 전액 환불(시간 초과·KG 거절 포함)이 영구히 `INDETERMINATE`로 남아 주문이 잠김 | 10분 뒤 재조회에서 결제사에 취소가 없으면 다시 처리하거나 중단할 수 있는 상태로 전환 |
| 환불 | 환불 자격 확인과 뽑기가 동시에 일어나면 오래된 수량으로 판단해 주문이 영구히 잠김 | 행을 먼저 잠그고 새 문장에서 수량을 셈 |
| 환불 | 부분 환불 계획이 시간 초과 직후 풀려, 늦게 도착한 카드 부분 취소를 반영하지 못함 | 같은 10분 대기 후에만 해제 |
| 환불 | 오래 걸린 취소 요청의 응답이 500 | 현재 행을 다시 읽어 응답 |
| 탈퇴 | 결제 완료(PAID) 주문이 영구 차단 항목이라 한 번이라도 결제한 고객은 탈퇴 불가(PAID→FULFILLED 전환이 없음) | 미결제·검토 중 주문만 차단. 남은 뽑기권·보관 상품은 원래대로 따로 차단 |
| 탈퇴 | 수락된 교환 제안이 교환 완료 뒤에도 차단 항목으로 남음 | 교환이 진행 중(MATCHED)일 때만 차단 |
| 교환 | 만료 정리 중 동시에 들어온 제안의 상품이 영구히 `EXCHANGE_OFFERED`로 남음 | 닫힌 글에 남은 대기 제안을 새 스냅샷으로 다시 정리(기존에 남은 것도 함께 정리) |
| 교환 | 신고로 글을 숨길 때 철회·거절된 예전 제안의 상품까지 풀어, 다른 글에 제안 중인 상품이 풀림 | 이번에 거절한 제안과 진행 중 교환의 수락 제안만 풀기 |

검증: DB 156, API 412 통과(2 skip), 워커 164 통과(로컬 PostgreSQL 17 전체 실행).

## 내일 할 것 (우선순위 순)

| # | 영역 | 문제 | 고칠 방향 |
|---|---|---|---|
| 1 | 탈퇴 | Apple 연결 기록은 있는데 Apple 갱신 토큰이 없으면 워커가 계속 실패해 탈퇴가 `PROCESSING`에 영구히 멈춤(로그인 불가·재요청 불가) | 처리 전에 토큰 유무를 확인해 재인증을 요구하고, 워커는 영구 실패 대신 `BLOCKED`로 되돌림 |
| 2 | 탈퇴 | 마지막 단계가 포인트만 다시 확인. 그 사이 잔액이 바뀌면 Supabase 계정은 이미 지워진 채 영구 실패 | 마지막 트랜잭션에서 차단 항목 전체를 다시 확인하고, 실패 시 복구 가능한 상태로 전환. 관리자 복구 경로 추가 |
| 3 | 결제 | 결제창을 연 직후 15분 예약이 끝나면 결제사 확인 없이 주문이 취소되고, 그 뒤 승인되면 돈만 받은 상태가 됨. 포인트를 함께 쓴 주문은 앱에서 늦은 환불도 막힘 | 결제창을 열 때 남은 시간이 충분한지 확인하거나 예약을 연장하고, 열린 결제창은 정리 전에 결제사에 다시 확인 |
| 4 | 결제 | 결제사 응답의 채널·금액이 서버 기록과 다르면 검토 기록 없이 오류만 남고 15분 뒤 주문이 정리됨(잡힌 돈을 아무도 모름) | 돈이 잡힌 불일치는 검토·알림 기록을 남기고, 그런 주문은 정리하지 않음 |
| 5 | 뽑기 | 미사용 뽑기 부분 환불 뒤 앱의 구매 복구 기록이 지워지지 않아(완료 확인이 취소된 뽑기권 때문에 409) 같은 상품을 다시 사기 어려울 수 있음 | 완료 확인에서 부분 환불로 취소된 뽑기권을 정산된 것으로 처리 |
| 6 | 배송 | 운영자가 배송 신청을 취소해도 결제한 배송비가 그대로 남음 | 배송비 주문을 검토 상태로 돌리거나 환불하고, 관리자 환불이 배송비 주문을 받도록 |
| 7 | 보관 | 카드사 취소 등으로 검토 중인 주문의 상품도 바로 배송·교환 신청 가능 | 배송·교환 자격에 결제 완료 상태 조건 추가 |
| 8 | 탈퇴 | 웹 탈퇴 상태 페이지가 '다시 확인 필요'로 돌아온 요청에서 503을 냄 | 워커가 차단 항목 전체를 기록하거나 웹이 그 형태를 받아들임 |
| 9 | 개인정보 | 탈퇴 시 분리 보관이 `updated_at`을 갱신해 파기 기산일이 탈퇴일로 밀림 | 분리 전 기산 시각을 함께 보관해 그 기준으로 판단 |
| 10 | 개인정보 | 웹 탈퇴 페이지의 소셜 확인이 연결 계정이 없을 때 Supabase 사용자를 남김 | 흐름 중에 만든 사용자면 서버에서 삭제 |

참고(낮음):
- 쿠지 판매 차단은 서버 정책이 아니라 상품을 판매 중으로 두지 않는 운영 규칙에 기대고 있다.
- 로컬에서 실패로 끝난 결제는 워커가 다시 조회하지 않는다. 앱은 재시도마다 새 주문을 만들어 위험은 낮다.
- 포인트 환급과 배송 신청이 같은 상품을 다른 순서로 잠그면 교착이 생길 수 있다. 한 요청이 실패하고 재시도로 풀리며, 돈 문제는 아니다.
