# 출시까지 남은 일 — 분석과 실행 계획 (2026-10-06)

목표: 친구 명의 계정으로 가챠 8종 판매판(LIVE)을 iOS·Android에 출시한다. 쿠지는 첫 출시 범위 밖이다.
이 문서는 코드로 끝낸 일, 코드로 남은 일, 사람이 결정·실행해야 하는 일을 나눈다. 명령 순서는
[`launch-operator-checklist.md`](launch-operator-checklist.md), 제출 자료는 [`store-submission-pack.md`](store-submission-pack.md)를 따른다.

## 1. 결론

- 출시 시점을 정하는 가장 긴 경로는 코드가 아니라 **KG이니시스 LIVE 승인 → 테스트 채널 실결제 검증**,
  **판매용 약관·개인정보처리방침 법률 검토**, **친구 명의 계정 이전(Google Play·Expo·GitHub·Supabase·로그인·푸시)**이다.
- 코드로 남았던 출시 차단 항목(일부 뽑기를 사용한 주문의 미사용분 환불)은 소유자가 권장안을 승인해 구현했다(3절 D1).
- 운영 DB·Edge·Cron에는 아직 반영하지 않은 변경(마이그레이션 0083~0087, 새 API)이 있다. PR 병합 후 체크리스트 1~5단계로 반영한다.

## 4. 실행 계획

### 단계 A — 지금 할 수 있는 것 (개발·운영자, 1~2일)

1. 이 PR을 병합한다.
2. 체크리스트 1~5단계: 백업 → 0083~0087 적용 → Edge 배포(PRELAUNCH) → 관리자 웹 재배포 → Cron 켜기.
   - Cron을 켜도 보관기한 자동 처리와 기록 파기는 돌지 않는다. 결제 대사·주문 만료·탈퇴 처리만 돈다.
3. 관리자 화면에서 가챠 8종 경품·수량·확률표를 검수하고 ACTIVE 게시한다(체크리스트 6단계).

### 단계 B — 친구 명의 계정 (친구, 병행)

[`friend-owned-release-accounts.md`](friend-owned-release-accounts.md) 순서대로 진행한다:
사업자 정보 일치 확인 → Google Play 앱 생성 → Expo Owner·GitHub 저장소 이전 → Supabase·Cloudflare·도메인·지원 메일 소유 확인
→ 카카오·네이버·구글·Apple 로그인 앱과 APNs/FCM 키 → 친구 계정으로 서명 빌드.

### 단계 C — 콘솔 검수 (친구, B와 병행)

- 네이버: 제공 정보 축소(체크리스트 7-1) → 검수 요청.
- 구글: OAuth 동의 화면 게시·검증. 카카오: 비즈 앱·검수.
- 각 제공자에서 실제 계정으로 로그인·재로그인·동의 철회 확인.

### 단계 D — 결정 (사용자·친구, 이번 주)

D1은 결정·구현됐다. D2(웹 탈퇴 포인트 소멸)를 정한다.

### 단계 E — 남은 코드 (개발, D1·D2 결정 후)

1. (완료) 미사용분 부분 환불: 관리자 결제 상세의 "미사용 뽑기 부분 환불", PortOne 부분 취소, 결제사 확인 후 반영, 재조회·잠금 해제, 고객 구매 내역 표시, 통합 테스트. 가챠만 대상이며 쿠지는 제외.
2. (D2 승인 시) 웹 탈퇴 포인트 소멸 동의: `worker/index.js`와 `public/legal/account-deletion/app.js`.
3. (LIVE 직전) 법률 검토본으로 `public/legal/terms`·`privacy`를 갱신하고 새 정책 버전 마이그레이션을 추가한다. 기존 회원에게 재동의가 표시된다.

### 단계 F — 법률 검토 (친구·법률 자문)

`docs/legal-drafts/`의 `[확인 필요]` 항목을 채우고 검토받는다. 포인트 소멸·분리 보관 조항이 들어 있다.

### 단계 G — PG (KG이니시스 승인 후)

1. 스테이징 테스트 채널에서 체크리스트 9-1 목록을 실제로 확인한다. 카드 결제·전액 환불, 혼합 환불, 포인트 주문 환불, 배송비 결제·환불, 15분 자동 취소, (구현 후) 부분 환불이 대상이다.
2. LIVE MID·채널키·웹훅·API secret을 받아 LIVE 프로필(`live-cutover-runbook.md`)을 준비한다.

### 단계 H — 판매판 빌드·제출

1. `production-live` 설정으로 친구 팀(`MCZ4884P7F`) 서명 빌드. iOS 빌드 번호는 5보다 크게.
2. 실기기 회귀: SNS 로그인 4종, 딥링크, 상품·결제 직전 화면, 보관함·배송 신청, 탈퇴(포인트 소멸 포함), 접근성, 심사자 로그인.
3. 스토어 심사자 로그인을 연다(체크리스트 7단계) → 제출 자료로 App Store·Play 제출.

### 단계 I — LIVE 전환

`live-cutover-runbook.md`: 판매판 승인·법률 검토본 게시·백업 확인 후
`node scripts/deploy-supabase-live-edge.mjs --confirm=LIVE:rconfxsykttfvznakile`. 실패하면 자동으로 PRELAUNCH로 돌아간다.
