# 다뽀바 개인정보 내부관리계획

시행일 2026-10-07 · 승인 대표 김정미

## 1. 목적과 적용 범위

- 다뽀바가 처리하는 회원·주문·배송·문의 정보가 분실·도난·유출·위조·변조·훼손되지 않도록 관리적·기술적·물리적 보호조치를 정한다.
- 적용 범위: 다뽀바 앱·웹(dabboba.net)·관리자 화면(admin.dabboba.net)·서버(Supabase)·작업 프로그램(worker)과 이를 다루는 모든 개인정보 취급자, 그리고 처리를 위탁받은 수탁자.

## 2. 조직과 역할

| 역할 | 담당 | 하는 일 |
| --- | --- | --- |
| 개인정보 보호책임자 | 대표 김정미 | 이 계획의 수립·승인·점검, 유출 대응 총괄, 이용자 권리 요청 처리 감독 |
| 개인정보 취급자 | 관리자 화면 계정을 받은 운영자 | 지정된 업무 범위 안에서만 개인정보 열람·처리 |
| 시스템 관리자 | 개발·운영 담당 | 서버·DB 권한, 배포, 백업, 접속기록 관리 |

- 취급자는 업무에 꼭 필요한 사람으로 최소한만 지정하고, 지정·변경·해제 내역을 기록한다.

## 3. 교육

- 취급자는 업무를 시작하기 전과 매년 1회 이상 개인정보 보호 교육을 받는다(유출 사례, 관리자 화면 사용 규칙, 이 계획의 내용).
- 교육 일시·대상·내용을 기록하고 보관한다.

## 4. 접근 권한 관리

- 관리자 화면 권한은 역할별(RBAC)로 업무에 필요한 최소 범위만 부여한다. 환불·탈퇴 처리 같은 권한은 해당 업무 담당자에게만 준다.
- 권한을 주거나 바꾸거나 회수한 기록은 관리자 감사 기록으로 남기고 최소 3년 보관한다.
- 퇴사·업무 변경 시 그날 안에 관리자 계정을 정지하고 Cloudflare Access 허용 목록에서 뺀다.
- DB 접근 권한은 앱·작업·관리 용도별 역할로 나누고, 운영 DB 직접 접속 정보는 시스템 관리자만 보관한다.

## 5. 접근 통제와 인증

- 관리자 화면은 Cloudflare Access(허용된 운영자 이메일, 2단계 인증)를 거친 뒤 관리자 비밀번호로 로그인한다.
- 관리자 비밀번호는 다른 서비스와 다르게 정하고 공유하지 않는다. 일정 횟수 이상 로그인에 실패하면 차단된다.
- 관리자 세션은 정해진 최대 시간이 지나면 다시 로그인해야 한다.
- 각 클라우드 계정(Supabase·Cloudflare·Expo·GitHub·Apple·Google)은 계정 2단계 인증을 켠다.

## 6. 암호화

- 모든 전송 구간은 HTTPS로 암호화한다.
- 로그인 세션은 해시값으로만 저장하고, Apple 갱신 토큰은 암호화해 저장한다.
- 카드번호·CVC·카드 비밀번호는 저장하지 않는다(결제창에서 결제대행사가 처리).
- 서버 비밀값(API 키, DB 접속 정보)은 서버 전용 저장소에만 두고 앱·코드 저장소·대화에 남기지 않는다.

## 7. 접속기록 보관과 점검

- 관리자 화면의 개인정보 처리 기록(누가, 언제, 무엇을)은 관리자 감사 기록으로 최소 1년 보관한다.
- 보호책임자 또는 지정한 사람이 월 1회 이상 감사 기록을 확인한다. 대량 조회, 업무 시간 밖 처리, 권한 밖 시도가 있으면 사유를 확인하고 기록한다.

## 8. 악성 프로그램 방지와 보안 업데이트

- 업무용 PC와 휴대폰은 운영체제와 백신을 최신으로 유지한다.
- 서버 의존성의 보안 취약점은 저장소 검사(CI)로 확인하고, 높은 위험은 확인 후 빨리 고친다.

## 9. 물리적 보호와 출력·복사

- 서버는 수탁자(Supabase·Cloudflare) 데이터센터에서 운영한다.
- 개인정보를 종이로 출력하거나 파일로 내려받지 않는 것을 원칙으로 하고, 불가피하면 업무가 끝난 뒤 바로 파기한다.

## 10. 백업과 재해 대비

- 운영 DB는 정기 백업과 시점 복구(PITR) 설정을 확인하고, 연 1회 이상 별도 환경에서 복원을 시험한다.
- 암호화한 백업 파일과 키는 서로 다른 장소에 보관한다.

## 11. 수탁자 관리·감독

- 수탁자와는 처리 목적·범위, 재위탁 제한, 안전성 확보, 손해배상 책임이 담긴 계약(또는 수탁자 약관·DPA)을 확인해 둔다.
- 연 1회 이상 수탁자 목록과 처리 내용이 개인정보처리방침과 맞는지 점검한다.

## 12. 유출 대응

- 유출을 알게 되면 즉시 원인 차단, 피해 확인, 접근 권한 회수부터 한다.
- 유출된 이용자에게 알게 된 때부터 72시간 이내에 유출 항목·시점·경위, 피해 최소화 방법, 대응 조치, 문의처를 알린다.
- 법령이 정한 경우(예: 1천 명 이상, 민감·고유식별정보, 외부 불법 접근)에는 72시간 이내에 개인정보보호위원회 또는 한국인터넷진흥원에 신고한다.
- 사고 경위와 조치를 기록하고 재발 방지 대책을 이 계획에 반영한다.

## 13. 파기

- 보관기간이 끝난 정보는 개인정보처리방침 2항과 운영자가 승인한 보존 정책(`docs/commerce-retention-components.md`)에 따라 파기한다.
- 파기 결과(대상, 건수, 일시)를 기록한다.

## 14. 점검과 개정

- 보호책임자는 연 1회 이상 이 계획의 이행 상태를 점검하고 결과를 기록한다.
- 서비스·수탁자·법령이 바뀌면 이 계획을 개정하고 개정 이력을 남긴다.
