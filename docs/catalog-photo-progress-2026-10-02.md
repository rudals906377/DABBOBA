# 운영 상품 사진 등록 — 2026-10-02

## 실제 진행 결과

- 친구 명의 운영 프로젝트 `rconfxsykttfvznakile`와 관리자 `다뽀바운영자`를 확인했다. FINDE와 다른 계정은 변경하지 않았다.
- 공개 가챠 8개, 구성 상품 46개를 확인했다. 기존 56개 고유 이미지가 HTTP 응답과 이미지 디코딩 검사를 통과했다. 추가한 3번 사진도 HTTP 200, WebP 1000×1000 디코딩 검사를 통과했다.
- 실바니안 상세 갤러리에 `1.jpg`, `2.jpg`, `3.jpg`를 원본 비율로 순서대로 등록했다. 공개 API에도 동일한 순서로 반영됐다. 숫자 사진을 경품 상품으로 추가하지 않았다.
- 관리자 화면에서 3번 사진 저장 성공을 확인했고, 상품 버전은 7이다. 상세 슬라이드 미디어 ID는 순서대로 `ac1ed9f4-51a3-49aa-8072-916e2fdbf56b`, `8a09f32c-63da-4498-8274-22a04e1a948a`, `767e97bb-bda5-42c7-b59b-551fec9861c0`이다. 대표 사진 `48d2f41d-84c4-4017-860c-4e16fafc5e1d`와 구성 상품 8종은 유지됐다.
- 상품 가격·재고·추첨 규칙·기본 대표 사진은 변경하지 않았다. 판매 상품 8개 모두 COMING_SOON이며 구매 불가 상태를 확인했다. PRELAUNCH 결제 차단은 유지했다.

## 수정 및 배포

- Storage 요청의 타임아웃 핸들에 Node 전용 `unref()`를 무조건 호출하던 코드가 운영 Edge 환경에서 `TypeError: timer.unref is not a function`으로 실패했다.
- `timer.unref?.()`로 변경했다. 숫자 핸들을 반환하는 Web/Edge 타이머 회귀 테스트에서 수정 전 실패·수정 후 통과를 확인했다. `clearTimeout` 호출도 검증한다.
- 운영 `dabboba-admin-api`만 새 번들로 배포했다. 고객 API·worker·비밀 설정은 변경하지 않았다. 이후 1·2번 사진은 실제 complete 응답 200과 READY 미디어 상태까지 확인했다.
- 이후 3번 업로드 요청은 Cloudflare Free Managed Ruleset의 `React - Leaking Server Functions - CVE:CVE-2025-55183` 규칙에서 차단됐다. 관리자 Worker에 도달하기 전의 차단이었고, IP·경로 예외나 유료 업그레이드는 적용하지 않았다.
- 사진 업로드만 React Server Action 대신 `/api/catalog/images`의 일반 multipart 요청으로 변경했다. 동일 출처·관리자 권한·서버 토큰·11MiB 스트림 제한·10MiB 파일 제한·감사 사유·세 단계 멱등 키·상품 버전 검사·이미지 정제는 유지했다. 오류를 성공으로 표시하거나 판매 차단을 우회하지 않는다.
- 관리자 업로드 수정 `a35d856`을 친구 명의 Cloudflare 계정에 배포했다. 배포 버전은 `aa253bb8-4838-4194-b132-1ad68efe2f47`이다. 기존 비밀 설정과 WAF 규칙을 보존한 상태에서 3번 사진 실제 저장에 성공했다.
- 별도로 공개 이미지 302 응답의 기본 `Cross-Origin-Resource-Policy: same-origin` 때문에 관리자 미리보기가 차단되는 현상을 재현했다. 공개·READY 상품 사진 검사에 통과한 리다이렉트만 `cross-origin`으로 응답하도록 수정 `3a15d5d`를 고객 `dabboba-api`에 배포했다. 비공개·없는 이미지의 404와 일반 API 응답은 기존 `same-origin`을 유지한다. Storage 버킷을 공개하거나 인증·서명 URL 검사를 제거하지 않았다.

## 검증 범위와 제한

- Node 24.19.0: media-storage 17개 테스트 통과, API Edge 핸들러 15개 테스트 통과.
- media-storage 타입 검사·빌드, Supabase 관리자 번들 생성, 변경 형식 검사 통과.
- 시스템 Node 25.8.1에서는 타임아웃 관련 테스트가 종료되지 않아 해당 런타임의 전체 통과를 주장하지 않는다. 이 현상의 원인은 확정하지 않았다.
- 관리자 전체 61개 테스트, 타입 검사, Cloudflare 빌드 및 산출물 검사 통과. 새 multipart 회귀 검사는 수정 전 실패·수정 후 통과했고, 교차 출처·권한 부족·오래된 버전·잘못된 파일·실제 스트림 초과·오류 정보 노출을 검사했다.
- 공개 이미지 CORP 회귀 검사는 수정 전 실패·수정 후 통과했다. 카탈로그 미디어 및 Edge 핸들러 23개 테스트, API 타입 검사, 고객 Edge 번들 생성 통과. 운영에서도 공개 사진 302는 `cross-origin`, 없는 사진 404와 일반 카탈로그 응답은 `same-origin`임을 확인했다.
