# 토스페이먼츠 직접 계약 · 서비스 심사 웹 전환

작성일: 2026-10-13. 로컬 코드 준비 상태이며, 배포·입점 승인·실제 토스 TEST 결제 성공을 의미하지 않는다.

## 확정 범위

- 대표자가 토스에 직접 신청한다. 포트원 토스 채널로 우회하지 않는다.
- 기존 `https://dabboba.net/review/`의 상품·사업자정보·로그인·배송/교환/환불/취소 안내 구성은 유지한다.
- 이니시스/KCP 선택과 SDK는 심사 화면에서 제거하고 토스 신용카드 TEST 결제창 요청으로 변경했다.
- 운영 상품·고객 데이터, 일반 판매 및 기존 네이티브 결제 방식은 이 작업으로 전환하지 않았다.

## 구현

1. 화면은 서버의 `tossPayment` TEST 설정이 있을 때만 결제 요청을 허용한다. 설정이 없거나 LIVE 키면 버튼을 끈다. 제출 직전 설정을 새로 확인한다.
2. 결제 금액은 현재 상품 표시가격이 아니라 서버가 생성한 주문 금액이다. 토스 `orderId`는 서버 `paymentId`다.
3. 복귀 URL의 금액·키는 지급 근거가 아니다. 서버가 주문 소유자·금액·상점 MID·통화·결제 상태를 확인한 뒤 기존 원장/주문/뽑기권 처리에 연결한다.
4. 승인 전 불변 승인 시도 기록(0096)을 먼저 저장한다. 응답이 끊기면 새 결제나 임의 취소 대신 조회 복구하며, 동일 주문의 중복 지급을 방지한다.
5. 승인 기록이 없고 토스 서버 조회로 미승인이 확인된 주문만 닫기 복구한다. 조회 오류는 미결제로 간주하지 않는다.
6. 시크릿 키는 서버에서만 사용한다. 브라우저에는 TEST 클라이언트 키만 제공한다. 결제 복귀 쿼리는 즉시 화면 주소에서 제거하며 카드·고객정보가 담긴 원본 PG 응답은 저장하지 않는다.
7. 이전 PG의 미확인 구매 기록은 토스 주문으로 재사용하지 않는다. 기존 기록을 삭제하거나 성공으로 덮어쓰지 않는다.

## 배포 전 남은 준비

### 2026-10-13 실환경 읽기 확인

- 결제시험 프로젝트 `lyzcyrdiazorjaqlgblr`의 CLI 접근과 공개 설정 조회가 성공했다. 현재 INICIS/KCP TEST 채널이며 토스 설정은 없다. 비공개 시험 프로필에도 토스 키는 아직 없다.
- 시험 DB에는 이력 83개가 있으며 마지막은 예전 파일명 `0082_portone_card_channel_binding.sql`다. 현재 저장소의 번호 변경 처리와 후속 마이그레이션을 검증해야 한다. 이미 적용된 동일 SQL을 다시 실행하거나 이력을 임의 삭제하지 않는다.
- 시험 API의 현재 필수 약관 버전은 `2026-09-30`, 운영 API는 `2026-10-07`이다. 후속 약관 마이그레이션은 해당 HTML 게시 순서를 지켜 적용해야 한다.
- 운영 프로젝트 `rconfxsykttfvznakile`의 공개 설정은 `PRELAUNCH`다. 이 확인 중 DB·시크릿·함수·사이트를 변경하지 않았다.
- Codex 브라우저의 토스 개발자센터는 로그인 화면으로 이동했다. 대표자 계정 로그인·TEST 상점 확인 전에는 키를 만들거나 가짜 값으로 대체하지 않는다.

- 대표자의 토스 개발자센터 계정에서 같은 TEST 상점의 API 개별 연동 클라이언트 키·시크릿 키·MID를 확인한다. 계약 전에도 회원가입 후 TEST 상점 키를 사용할 수 있다. 키 값은 채팅·Git·스크린샷에 남기지 않는다.
- 2026-10-13 사용자 승인으로 보호된 `worker/index.js`의 `/review/` 전용 CSP를 변경했다. 스크립트는 `https://js.tosspayments.com`, 결제 연결·프레임·폼은 토스 소유 HTTPS 하위 도메인만 허용한다. 이전 심사 경로의 PortOne/이니시스/KCP 허용은 제거했다. 인라인 스크립트·eval 허용은 추가하지 않았다. 복귀 정보가 Referrer로 전달되지 않게 심사 경로만 `no-referrer`를 적용했다. 휴대폰 프레임·다른 경로의 정책은 그대로다. **배포 전이므로 실제 사이트는 아직 이전 설정이다.**
- STAGING 백업·마이그레이션 이력을 확인한 뒤 0096과 미적용 선행 마이그레이션을 순서대로 적용한다. 운영 DB에 시험 주문을 만들지 않는다.
- STAGING API 설정은 `PAYMENT_PROVIDER=TOSSPAYMENTS_DIRECT`, 두 환경 등급 `STAGING`, 같은 TEST 상점의 `TOSS_PAYMENTS_CLIENT_KEY`, `TOSS_PAYMENTS_SECRET_KEY`, `TOSS_PAYMENTS_MERCHANT_ID`다. 기존 PortOne 자격 증명은 이 프로필에서 함께 설정하지 않는다. 프로젝트 경계는 `lyzcyrdiazorjaqlgblr`로 고정된다.
- Edge 설정 이름은 `DABBOBA_API_TOSS_PAYMENTS_CLIENT_KEY`, `DABBOBA_API_TOSS_PAYMENTS_SECRET_KEY`, `DABBOBA_API_TOSS_PAYMENTS_MERCHANT_ID`다. 기존 프로필 생성/배포 스크립트의 PortOne 전용 검증도 별도 전환한 뒤 배포한다. 검증을 우회해 수동 LIVE 배포하지 않는다.
- 심사 계정/API의 만료 및 비밀번호 유효성을 실제 로그인으로 다시 확인한다. 기존 웹 프록시 만료는 2026-10-31 23:59 KST이며 자동 연장하지 않았다.
- 승인된 CSP·새 API·공용 사이트를 배포한 뒤 실제 토스 TEST 창, 성공 복귀, 닫기, 오류 복구 및 기존 사업자/정책/상품 노출을 PC와 휴대폰에서 확인한다. 제출 완료나 PG 수락을 아직 주장하지 않는다.

## 검증 범위와 한계

- 설정 단위검증: 40건 통과. 운영 프로젝트·LIVE 키·불완전 설정 차단 포함.
- 심사 페이지/프록시/공용 사이트 회귀 45건 통과. 토스 전용 허용 목록·이전 PG 제외·기존 로그인 보호 유지·일반 홈페이지/약관/개인정보/고객지원/회원탈퇴 경로 격리를 확인했다. 이는 로컬 코드 검증이며 배포된 응답 헤더나 실제 토스 결제창 성공의 증거는 아니다.
- 토스 어댑터: 주문·금액·MID·통화·응답 형태·네트워크 오류·취소 시각 검증. 실제 토스가 아닌 합성 HTTP 응답을 사용했다.
- 실제 일회용 PostgreSQL 통합시험: 전체 마이그레이션, 주문 예약, 1회 지급, 미승인 종료, 승인 응답 유실 후 조회 복구, 불변 기록과 역할 권한. PG 통신만 합성이다.
- 브라우저: 390×844, 1280×900의 화면·입력·서버 금액·복귀 정보 제거·준비 전 버튼 차단을 합성 API/SDK로 확인했다. 실제 토스 창·실기기 결제 증거는 아니다.
- CSP 추가 브라우저 시험: 로컬 390×844 환경에서 실제 Worker 응답 헤더와 빌드된 정적 파일로 토스 공식 SDK가 로드되어 `TossPayments`가 정의되는 것을 확인했다. 이용 안내 링크 동작·관련 콘솔 오류 없음·인라인 스크립트 차단도 통과했다. API만 합성이며, SDK 초기화·결제 요청·카드 입력·PG 승인은 하지 않았다. 보호 파일 무결성과 웹 빌드·Expo TypeScript 검사도 통과했다. 빌드의 기존 큰 청크/모듈 유형 경고는 남아 있으며 이번 변경으로 처리하지 않았다.
- 운영용 토스 웹훅/재조회 작업자/관리자 환불 및 iOS·Android 결제창 통합은 미완료다. 따라서 운영 직접 토스 설정은 코드에서 차단한다. 시험용 시크릿으로 운영 결제를 켜지 않는다.
