# 관리자 상품 운영 연결

## 환경을 먼저 구분하기

관리자는 별도 `apps/admin` 앱이며, 고객 앱이나 DB에 직접 관리 권한을 넣지 않는다.

- 관리자 `DABBOBA_API_URL`: `/v1/admin/*`를 제공하는 관리자 API 주소. Supabase 함수 경로가 있으면 그 경로까지 포함한다.
- API `DABBOBA_CATALOG_MEDIA_BASE_URL`: 고객이 상품 이미지를 읽는 고객 API의 공개 기본 주소. 관리자 API 주소와 다를 수 있다.
- 고객 앱 API 주소: 해당 관리자와 같은 승인된 카탈로그 DB를 조회하는 환경이어야 한다. 로컬 앱을 원격 운영 DB로 자동 전환하지 않는다.
- 운영은 HTTPS를 사용한다. 로그인 프록시의 IP 서명 설정과 안전한 세션 쿠키를 유지한다.
- 고객용 API에 관리자 라우트를 공개해서 연결 문제를 해결하지 않는다.

예를 들어 함수 경로가 있는 경우 기본 주소는 `https://<project>/functions/v1/<function>` 형식이다. 실제 프로젝트·함수 이름은 배포 결과로 확인하며 이 문서의 예시를 그대로 운영 설정으로 사용하지 않는다.

## 상품·재고·확률표

1. 상품 정보는 관리자 상품 화면에서 저장한다. 기존 상품의 카테고리와 경품 전용 여부는 변경하지 않고 새 SKU로 구분한다.
2. 재고는 재고 운영에서 조정한다. 최고 관리자 권한, 변경 전 버전, 조정 사유를 확인하며 증감은 별도 불변 원장에 남는다. 상품 사진이나 가격 수정으로 재고를 덮어쓰지 않는다.
3. 가챠는 가중치와 유한 수량을 입력한다. 현재 예상 확률은 각 항목의 `가중치 × 남은 수량` 비중이다.
4. 쿠지는 전체 장수와 등급별 수량·코드·순서를 입력한다. 수량 합계가 전체 장수와 같아야 하며 가챠 가중치를 입력하지 않는다.
5. 초안 저장과 공개는 별도 작업이다. 공개된 버전은 직접 수정하지 않으며 새 초안을 검토해서 교체한다. 실물 재고의 중복 배정 여부는 별도 입고·검수 원장과 대조한다.
6. 고객 앱은 다음 카탈로그 조회/새로고침에 저장 결과를 읽는다. 관리자 저장이 이미 열린 모든 고객 화면을 즉시 바꾼다는 의미는 아니다.

## 사진 연결 원칙

- 관리자 상품 목록의 `사진`을 열고 파일과 변경 사유를 입력한 뒤 `사진 업로드 및 연결`을 누른다. JPG/PNG/WebP/GIF, 최대 10MB를 지원한다. 오류가 나면 저장 완료로 간주하지 않는다.
- 관리자 권한으로 상품용 업로드를 시작하고, 실제 업로드 파일을 서버에서 검사한 뒤 READY 상태의 본인 업로드만 연결한다.
- 파일 크기·내용·체크섬·이미지 디코딩을 확인하고 메타데이터를 제거한 결과를 사용한다. 확장자나 브라우저의 성공 표시만 신뢰하지 않는다.
- 상품에는 만료되는 저장소 서명 URL 대신 안정적인 고객 API 이미지 주소를 저장한다. 고객 API는 공개 가능한 참조를 확인하고 짧게 유효한 저장소 읽기 주소로 연결한다.
- 다른 운영자가 먼저 수정한 상품은 버전 충돌로 중단한다. 사진 수정은 해당 상품의 이미지와 버전만 변경한다.
- 상품에 한 번 연결한 이미지와 과거 뽑기·배송 스냅샷은 보존한다. 단순 파일 정리로 판매 기록의 사진을 지우지 않는다.
- 기본 대표 사진은 상세 슬라이드가 없는 상품의 대체 사진이다. `새 상세 슬라이드 사진`을 차례로 추가하면 고객 상세 화면은 그 사진들만 등록 순서대로 넘겨 보여준다(최대 8장). 목록 사진과 경품 종류별 사진에는 영향을 주지 않는다. 관리자 화면에서 슬라이드 한 장씩 연결 해제할 수 있다. 다른 관리자의 변경으로 상품 버전이 바뀌면 새로고침 후 다시 시도한다.
- 로컬 `재고상황/가챠/실바니안 패밀리 아기 어드벤쳐 시리즈/1.jpg`, `2.jpg`, `3.jpg`는 3개의 상세 슬라이드 원본이다. **경품 종류나 별도 재고 3종이 아니다.** 이 공통 기능은 다른 상품에도 사용할 수 있다. 로컬 사진의 존재만으로 운영 업로드·사진 권리·실물 재고 검증을 완료한 것으로 보지 않는다.

## 운영 적용과 코드 검증의 차이

현재 Node 이미지 검사 파이프라인을 사용한다. 동등한 검사기가 제공되지 않은 Edge 실행 환경은 사진 완료 처리를 503으로 거절한다. 새 상품 업로드도 검사기나 제공 주소가 없으면 시작하지 않는다. 설정 없이 성공으로 표시하거나 검사를 생략하면 안 된다.

실제 운영 완료에는 운영 관리자 계정 발급, 관리자/고객 API 배포 주소, 비공개 저장소와 검사 런타임 설정, 실제 업로드와 기기 표시 검증이 따로 필요하다. 최초 관리자 발급 절차는 `docs/dabboba-operations-runbook.md`의 "첫 관리자 만들기"를 따른다. 비밀번호·서비스 키는 채팅이나 저장소에 기록하지 않는다.

2026-09-09 격리 테스트 결과는 저장소 밖 `output/admin-validation-2026-09-09/verification.md`에 기록한다. 해당 검증용 계정·상품은 실제 운영 계정·판매 상품이 아니다.
