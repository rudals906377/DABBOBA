# DABBOBA 내부 테스트 결제

## 승인 범위

2026-09-12: 실제 돈이 나가지 않는 앱 내부 테스트 결제와 예시 상품을 사용한다. 기존 상품 원본을 보존할 필요는 없다는 사용자 결정을 반영하되, 과거 주문·추첨·사용자 기록은 삭제 대상이 아니다. 기존 DABBOBA Supabase 프로젝트를 사용하고 고정 실행 파일은 유지한다.

## 구현 경계

- 명시적으로 선택한 `supabase-demo` 프로필에서만 테스트 기능을 연다. 일반 통합·운영 프로필에는 테스트 결제나 임의 로그인 우회가 없어야 한다.
- 내부 고객 계정은 `da000000-0000-4000-8000-00000000000a` / `member01@dabboba.local` 하나만 `ACTIVE`로 유지한다. 이 계정의 가격·재고·추첨 결과·보관함·포인트는 서버 트랜잭션으로 저장한다.
- UUID와 이메일은 고정된 내부 테스트 식별자지만 닉네임 등 프로필 정보는 일반 고객과 동일한 수정 가능 데이터다. 프로필 변경을 계정 불일치나 초기화 사유로 삼지 않는다.
- 고객 화면에는 `DEMO`, 테스트 계정 문구, A/B 계정 선택기를 노출하지 않는다. `TEST_PG`와 실제 청구가 없다는 안내는 사실성을 위해 개발 전용 결제 컨트롤 안에서만 표시한다.
- 중복 내부 계정은 로그인을 차단하고 기존 세션을 폐기해 퇴역시킨다. 주문·결제·추첨·보관함·포인트 원장·감사 이력은 원래 사용자 ID에 그대로 보존하며 계정을 병합하거나 하드 삭제하지 않는다.
- 모바일 고객 경로는 퇴역한 `mobile-test@dabboba.local` 계정을 자동 생성·복구하거나 연결 실패 시 대체 계정으로 사용하지 않는다. 유효한 단일 계정 세션이 없으면 게스트 상태를 유지한다.
- 실제 카드정보 입력, PG 결제/환불 호출, 배송장 구매, SMS·메일·푸시 발송, Worker/Cron 활성화는 하지 않는다.
- 단위·동시성·초기화 테스트는 폐기 가능한 로컬 TEST DB에서 한다. Supabase에서는 사용자가 승인한 예시 레코드만 대상으로 횟수가 제한된 기능 검증을 한다.

## 확인 기준

| 동작 | 완료를 판단하는 증거 |
| --- | --- |
| 로그인 | 서버가 단일 canonical 계정의 세션만 발급하고 재시작 후 같은 UUID·이메일과 `ACTIVE` 상태 확인; 퇴역 계정 로그인·기존 세션 거부 |
| 프로필 | 닉네임 변경 뒤에도 같은 UUID·이메일의 고객으로 유지되며 결제·보관함 이력 보존 |
| 결제 | 내부 테스트 승인 뒤 주문 조회에서 PAID, 재시도 시 이중 승인·이중 지급 없음 |
| 가챠 | 서버 확률표에 따라 확정된 결과와 보관함 기록, 같은 entitlement 재요청 시 같은 결과 |
| 쿠지 | 서버 대기방·결제 기한 유지, 구매 수량만큼 봉인 티켓 선택·소비, 잔여 수량 일치 |
| 실패·취소 | 미결제 주문 종료와 예약 재고 해제 |
| 환불 | 소비 전 테스트 주문의 환불 기록과 재고·권한 정리; 사용된 자산의 안전 경계 유지 |
| 포인트 환급 | 직접 뽑은 보관 중 가챠만 처리, 불변 원장과 잔액 일치 |
| 배송 신청 | 고객이 직접 저장한 배송지와 선택 상품만 신청 기록에 저장; 외부 발송 없음 |
| 교환 | 일반 고객용 소유권·예약 규칙을 유지하되 내부 검증을 위해 두 번째 로그인 계정을 만들지 않음 |
| 화면 | 네이티브 앱의 일반 고객 동선에 `DEMO`·테스트 계정·A/B 선택기가 없고, 개발 전용 결제 컨트롤에만 `TEST_PG`·실제 청구 없음 표시 |

위 표는 검증 기준이며 완료 보고가 아니다. 실제 실행 결과는 아래에 별도로 기록한다.

## 검증 기록

- 구현 전 원격 읽기 확인: 상품 25개, 사용자 1명, 주문 1개, 추첨 결과 4개. 기존 거래 기록은 그대로 둔다.
- 연결 변경 전 기준 검사: 격리된 `127.0.0.1:55441/dabboba_edge_test`에서 commerce, kuji-rooms, kuji-slots, exchange, account-shipping 통합 검사 5/5 통과(건너뜀 0). 기존 모바일 주문 복구·쿠지 주문·교환 검사 24/24 통과. 이는 새 데모 기능의 완료 증거와 구분한다.
- 보호된 런타임 28개 파일 무결성 검사, 기존 프로필/테스트 환경 안전 검사 9/9, 공용 패키지/API 빌드와 웹 빌드 통과. 웹 빌드에는 기존 대형 번들 경고가 남아 있다.
- 구현·실행 검증 진행 중. 실제 PG 결제, 실물 배송, 외부 인증·알림, 스토어 출시 완료를 의미하지 않는다.
- 2026-09-12 Supabase staging 확인: canonical 고객 1명만 `ACTIVE`, 중복 내부 계정 2명은 `BANNED`, 기존 활성 세션 13개는 폐기했다. 중복 계정의 기존 주문 3건과 보관 상품 5개는 원래 사용자 ID에 보존했고, 자동 생성 배송지 2개만 제거했다.
